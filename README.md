# Two-Factor Authentication (2FA) for Django Admin

This project implements **Two-Factor Authentication (2FA) for Django Admin**, enhancing security by requiring an additional authentication step beyond passwords. It supports multiple verification methods including **TOTP (Time-based One-Time Passwords)**, email, SMS, and phone calls.

## Features

- 🔒 **Multiple 2FA methods**:
  - **TOTP** via authenticator apps (Google Authenticator, Authy, Microsoft Authenticator)
  - **Email verification codes**
  - **SMS verification codes** (requires additional setup)
  - **Phone call verification** (requires additional setup)
  - **Backup codes** for emergency access

- 🛡️ **Enhanced security features**:
  - **Trusted device management**
  - **Rate limiting** for code generation
  - **Session-based verification**
  - **Secure cookie handling**

- 🎨 **User-friendly interface**:
  - **Mobile-responsive UI** with Tailwind CSS
  - **Clear error messages**
  - **Automatic code generation** for new users

## Technologies Used

- **Django** - Web framework
- **Redis** - For storing verification codes
- **PyOTP** - For TOTP implementation
- **Tailwind CSS** - For responsive UI

## Setup

1. Install dependencies:
   ```
   pip install -r requirements.txt
   ```

2. Set up Redis (required for storing verification codes):
   ```
   # Example with Docker
   docker run -d -p 6379:6379 redis
   ```

3. Configure environment variables in a `.env` file:
   ```
   SECRET_KEY=your-secret-key
   REDIS_HOST=localhost
   REDIS_PORT=6379
   ```

4. Run migrations:
   ```
   python manage.py migrate
   ```

5. Create a superuser:
   ```
   python manage.py createsuperuser
   ```

6. Run the development server:
   ```
   python manage.py runserver
   ```

## Usage

1. Log in to the Django admin interface at `/admin/`
2. You'll be redirected to the 2FA verification page
3. Enter the verification code sent to your email or generated by your authenticator app
4. You can check "Trust this device" to skip 2FA verification on this device for 30 days
5. After successful verification, you'll be redirected to the admin dashboard

## Managing 2FA Settings

You can manage your 2FA settings at `/2fa/settings/`:

- Enable/disable TOTP authentication
- Generate backup codes
- Change your preferred verification method
- Manage trusted devices

## Implementation Details

The 2FA system consists of several components:

1. **Models**:
   - `TwoFactorAuth`: Stores 2FA settings for each user
   - `TrustedDevice`: Stores trusted device information

2. **Middleware**:
   - `TwoFactorAuthMiddleware`: Enforces 2FA for admin paths

3. **Views**:
   - `verify_2fa`: Handles 2FA verification
   - `send_2fa`: Sends verification codes
   - `setup_totp`: Sets up TOTP authentication
   - `manage_2fa_settings`: Manages 2FA settings

4. **Services**:
   - `TwoFactorService`: Provides 2FA functionality
   - `RedisManager`: Manages code storage and verification

## Troubleshooting

- If you're having issues with Redis, make sure it's running and accessible
- Check the console for error messages when sending verification codes
- For development, verification codes are printed to the console
- If you encounter an error like "Cannot query 'email': Must be 'User' instance", make sure the AUTH_USER_MODEL setting is properly set in settings.py to 'authentication.User'
- If you encounter an error like "create_superuser() missing 1 required positional argument: 'username'", the project has been updated with a custom UserManager that fixes this issue
- If you encounter an error like "Please enter the correct Email and password for a staff account", make sure you're using the correct email and password, and that the user has staff privileges. The project now includes a custom authentication backend that properly handles email-based authentication.
- If you encounter a "TemplateDoesNotExist" error for 2FA templates, make sure the template paths in the views are correctly set to "authentication/2fa/template_name.html" instead of just "2fa/template_name.html".

## Handling GitHub Push Protection

If you encounter an error like "Repository rule violations found" when pushing to GitHub, it may be because GitHub has detected sensitive information (like AWS credentials) in your commit history. Here's how to resolve this issue:

### Option 1: Allow the Secret (Not Recommended for Real Credentials)

You can follow the URL provided in the error message to allow the secret if it's a test credential or no longer valid:
```
https://github.com/YourUsername/YourRepo/security/secret-scanning/unblock-secret/SECRETID
```

### Option 2: Remove Sensitive Data from Git History (Recommended)

To properly remove sensitive data from your Git history:

1. Install the BFG Repo-Cleaner:
   ```
   # For macOS with Homebrew
   brew install bfg

   # For other systems, download from https://rtyley.github.io/bfg-repo-cleaner/
   ```

2. Create a text file named `secrets.txt` with the sensitive data to remove:
   ```
   AKIAXXXXXXXXXXXXXXXX  # Replace with your actual AWS Access Key ID
   XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX  # Replace with your actual AWS Secret Access Key
   # Add any other sensitive strings
   ```

3. Run BFG to clean your repository:
   ```
   # Clone a fresh copy of your repo
   git clone --mirror https://github.com/YourUsername/YourRepo.git repo-mirror

   # Run BFG to replace sensitive data
   bfg --replace-text secrets.txt repo-mirror

   # Clean up and push changes
   cd repo-mirror
   git reflog expire --expire=now --all
   git gc --prune=now --aggressive
   git push
   ```

4. Delete the `secrets.txt` file securely after use.

### Option 3: Create a New Repository (Simplest Solution)

If the above options are too complex, you can:

1. Create a new repository on GitHub
2. Push your current code (with sensitive data removed) to the new repository
3. This approach loses commit history but is the simplest solution

### Prevention for the Future

- Always use environment variables for sensitive data
- Add `.env` to your `.gitignore` file (already done in this project)
- Consider using a secrets management tool like HashiCorp Vault or AWS Secrets Manager
- Use pre-commit hooks to prevent committing sensitive data
